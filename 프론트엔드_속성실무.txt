3. JS 기본 문법 시간 2 - 조건문, 반복문
조건문은 boolean 형이 조건문의 실행 여부를 결정 지음
if(true){} 일 경우 조건문 바로 옆의 중괄호가 실행되고, 아니라면 연쇄적으로 else fi() 문을 통해 맞는 조건을 찾아 떠남
모든 조건 중에 일치하는 게 없다면 최종적으로 else{} 문에서 조건문이 마지막으로 실행되고 마침
반복문은 for(변수, 조건, 증가 또는 감소형태) 로 구성되어 있음
변수 부분에서는 let i=0; 과 같이 반복문의 시작 위치를 숫자로 선언
조건에선 언제까지 반복시킬 것인지를 결정
증가 또는 감소 형태에서는 반복문에서 변수를 어떤식으로 증가 또는 감소 시킬 지를 결정
이 둘을 이용해 복잡한 객체 배열 구조의 데이터에서 원하는 데이터를 취할 수 있음

2. 물어보는 기술도 능력 - 검색 방법과 공식문서
[수업 요약]
구글에 검색하자 네이버보다 훨씬 많은 전세계 데이터가 존재한다
개발은 어쩔수 없이 영어가 베이스인 분야로, 영어로 검색 해버릇 하고 영어 단어로 키워드화 하는 연습을 해보자. 예컨대 앞으로 배울 css에서 글자 색을 바꾸는 방법을 찾는다면, css font color 식으로 생각해서 검색해버릇 해야한다.
키워드에 how to를 붙이면 방법에 대한 질문들이 잘 걸러져서 나온다
검색할땐 반드시 개발 관련 용어를 담아야 한다 예컨대 글짜 색을 바꾸려면 어떻게 해야하는지 how to change font color라고 했다면 앞이나 뒤에 css를 붙여주자 뭘할때 글자색을 바꾸는지는 알려줘야 한다
날짜를 1년으로 바꿔서 검색해보고 점점늘려가자. 프로그래밍은 시시각각 변화하고 새로운것들이 나온다. 반대로 기존건 없어지기도 한다
개발관련 검색을 하다보면 스택오버 플로우(stackoverflow) 사이트를 자주보게 된다. 이 사이트에서 주의해서 보야 할점은 질문 다음의 답변의 채택 숫자다. 숫자가 5이상이면 한번 보고 시도 할만 하다
그러나 또 눈여겨 봐야할 글은 답변의 코멘트들이다. 코멘트에서 해당 답변을 작성한 글쓴이와 이 답변을 본사람들이 얘기를 하며 답변을 디벨롭 할수도 있고, 결국 잘못 됐다라는 결론을 볼 수도 있어 시간을 절약 할수 있다

1. 웹과 서버의 동작 방식 이해하기
웹과 서버는 어떤 관계일까?
한줄로 말할 수 있다면, "데이터를 주고 받고 하는 사이"
좀더 긴 한 줄로 말하면, "정해진 규칙에 따라 데이터를 주고 받고 하는 사이"
조금 더 긴 한 줄로 말하면, "정해진 규칙에 따라 그림 파일 또는 텍스트 데이터를 주고 받고 하는 사이"
API는 바로 그 정해진 규칙! <- 서버 개발자가 만들어 놓음
API 규칙에 따라 프론트 개발자와 백엔드 개발자가 서로 프론트 작업 밴엔드 작업을 진행
동일한 API 주소도 각기 다른 통신 방식으로써 다른 기능을 할 수 있음
GET, POST -> 자세한 내용은 다음시간에!

2. 알고 시작하면 편한 API와 통신방식 GET, POST
GET은 주로 데이터나 그림 파일을 요청 할 때 사용하는 통신 방식
www.api.com?key=value 의 형태로 데이터를 서버개발자에게 보낼 수도 있음
그러나 민감하지 않은 데이터를 보낼때만 사용!
POST는 데이터를 서버 개발자에게 보낼 때 사용
브라우저 도메인에 POST 통신방식 API 주소를 입력해도 우리는 데이터를 확인 할 수 없음
추후에 배울 통신 코드, ajax 와 같은 코드단에서 POST 방식을 사용해야함
데이터 삭제, 수정, 저장등에 주로 사용하는 통신 방식
그럼 GET, POST 통신 방식은 누가 결정짓는건가요? ⇒ 서버개발자가 정합니다. 서버단에서 이 도메인은 GET 방식, 이 도메인은 POST 방식이라며 정해놔요!

$.ajax({
    // 클라이언트가 요청을 보낼 서버의 URL 주소
    url: `www.api.com`.
    // 요청과 함께 서버로 보낼 데이터 POST 방식에서만 사용
    data: {},
    type: "POST", // HTTP 요청 방식(GET, POST)
    success: function(json){},
    error: function(e){}
})

6. HTML, CSS 그림 파일 보여주기 (with 템플릿엔진 EJS)
그림 파일은 어떤 폴더에서 꺼내 보여줄 것인지, 그리고 그림 파일을 보여줄 때 동시에 데이터도 전달해줄 때는 어떤 도구를 사용할 것인지 app.js에 세팅을 해야합니다.
우리에게 익숙한 태그 형식의 문법으로 HTML 파일에서 서버로부터 가져온 데이터를 연결할 수 있는 ejs 템플릿 엔진을 사용합니다.
views 폴더에 HTML 파일 확장자명이 ejs로 된다는거 외엔 달라진게 없어요! 똑같이 HTML을 화면에 그려주는가 동시에 데이터도 같이 화면에 보여준다 정리해보고 바로 코드로 확인해봅시다.
서버의 기본적인 구조를 설정할 땐 app.set을 사용합니다.

//파일 위치:app.js
//express 도구를 불러오는 부분
//도구를 불러와 변수에 담아 사용합니다.
const express = require('express');
const helmet = require("helmet");
const ejs = require("ejs");

//결국 express도 많은 기능을 담고 있는 자바스크립트 함수로 볼 수 있으므로
//express 함수가 반환하는 서버 기능들을 다시 app에 담아 사용합니다.

const app = express();

app.set('view engine', 'ejs');
app.set('views', './views');

app.use(helmet());

//분리한 라우터(주소)들을 한 곳에 가져옵니다.
const mainRouter = require('./router/mainRouter.js')

app.use('/', mainRouter)

//서버를 켜는 코드입니다.
//3000은 컴퓨터의 몇 번방을 사용할 것인지, 즉 포트에 대한 설정을 하는 부분입니다.
app.listen(3000, function () {
 console.log('Example app listening on port 3000!');
});

그림파일을 내보낼땐, res.send가 아닌 res.render를 사용합니다.
// 파일 위치: /router/mainRouter.js
const express = require('express')
const router = express.Router()

// Home page route
router.get('/', function (req, res) {
 res.render('index.ejs',{"title":"class101 웹개발자 사관학교"})
})

router.post('/', function (req, res) {
 res.send({"key":"value"})
})

// About page route
router.get('/about', function (req, res) {
 res.send('어바웃 페이지')
})

module.exports = router

Sequelize는 Mysql을 더 쉽게 사용하는 도구 입니다. 그냥 파리채가 아닌 전기파리채 정도로 이해해주세요!
쉽게 사용한다는 뜻은 코드단에서 SQL 쿼리, 즉 Mysql 문법을 몰라도 데이터베이스 조작이 가능하게끔 해준다는 뜻입니다.
이 역시 npm 명령어 도구를 통해 Sequelize 도구를 여러분 Node.js 프로젝트에 설치하면 준비끝입니다 순서대로 설치 명령어를 vscode 터미널 복붙해 쳐보도록 하겠습니다.
그림과 같이 오른쪽 상단의 분할 버튼을 눌러주세요. 여러분 프로젝트를 바라보고 있는 검은화면을 두 개 여는거랍니다.

두 도구를 설치했다면, model 폴더의 db.js 파일에 다음 코드를 옮겨 넣어보세요
(** 주석을 아주 상세히 달아놨으니, 시간을 두고 천천히 한번 읽어보세요!)

//우리가 사용할 sequelize 라이브러리를 설치합니다.
var Sequelize = require("sequelize");

//대문자 Sequelize를 통해 연결한 결과를 받을 소문자 sequelize 변수를 뒀습니다
//이 이름은 마음껏 지어도 무방합니다.
var sequelize;

//sequelize 변수에 연결 정보를 담습니다. 
//연결정보 마저 Sequelize 도구에서 제공해주는 형식 그대로 사용할 뿐입니다.
sequelize = new Sequelize("class101", "root", "roodo102", {
 host: "localhost",
 port: 3306,
 dialect: "mysql",
 timezone: '+09:00', //한국 시간 셋팅
 define: {
  //sequelize는 기본적으로 영어 복수이름으로 테이블을 만드는데
  //그 기능을 끄는 옵션입니다.
  freezeTableName: true,
  charset: "utf8",
  collate: "utf8_general_ci",
  timestamps: true,
 }
});

var db = {};

//객체식으로 데이터베이스 테이블을 구성하고, 직접 해당 테이블에 접속을 할 수 있습니다
//따라서 이런 ORM 방식을 통해, 직접 쿼리를 날리지 않아도 테이블 정보가 담긴 객체를 이용하여
//데이터 조회,생성,변경,삭제를 할 수 있습니다.

db.users = sequelize.import(__dirname + "/users.js");

//추후에 연결된 sequelize 객체를 통해, 직접적으로 데이터베이스에 쿼리도 날릴 수 있습니다
//그래서 앞으로 우리가 사용할 db 객체에 sequelize 객체와 바로 위에서 만든 모델들을 채워 넣습니다.

db.sequelize = sequelize;
db.Sequelize = Sequelize;

module.exports = db;

지난시간에 생성했던 데이터를 이용해 데이터 변경/ 삭제 API를 만들어봅니다.

[데이터 변경 API]
지난시간에 생성했던 user_id는 898 이였습니다. 이 데이터를 다음과 같이 지울 수 있습니다. 지울 user_id는 받아 데이터를 삭제하는 POST 방식의 API라 정해봅시다.
router.post("/data/update", function(req,res){
  let target_id = req.body.target_id;

  db.users.update({user_id:9999},{where:{user_id:target_id}}).then(function(result){
    res.send({success:200})
  })
})

외부로부터 전달 받은 데이터는 req.body에 들어있으므로, 해당 body에서 target_id를 꺼내 변수에 담습니다. 물론 외부에서 전달할때 target_id라는 키값으로 전달할거에요!

update 함수엔 두 객체를 전달하는데, 하나는 변경하려는 모델 속성값과 변경 값의 쌍, 그리고 변경하려는 데이터 키값을 지칭해서 전달해줘야합니다. 쉽죠? 우리가 model 폴더에 만든 users 파일 값들을 매칭시켜주기만 하면됩니다.
그럼 다시 조회를 해서 변경됐는 지 확인해봅시다.

[데이터 삭제 API]
데이터 변경 API와 동일하게 삭제할 타겟 아이디를 받은 뒤 데이터를 삭제하는 시나리오입니다.
router.post("/data/delete", function(req,res){
  let target_id = req.body.target_id;
  db.users.destroy({where:{user_id:target_id}}).then(function(result){
    res.send({success:200})
  })
})

삭제 API를 실행 후 조회 API를 실행시키면 데이터 값엔 빈 리스트만 전달되고 있습니다. 즉 현재 users 테이블엔 아무 데이터도 존재하지 않는거죠!
지금까지 테니스로 치면 계속해서 서브만 넣었습니다. 즉 프론트 개발자와의 상호 소통이 아닌, API를 만들고 해당 API에 대한 기능과 결과에만 집중한거였죠!
이제 다음시간에는 1교시때만들었던 영화 리뷰 사이트와 여러분들이 만들 서버 API를 통해 온전한 하나의 웹 서비스가 어떻게 프론트와 백엔드 상호 대화를 통해 작동을 하는지 직접! 만들어보도록 하겠습니다

3. 리뷰 저장 API 만들기 (+ 고급기술!)
항상 API를 만들때는 테스트를 위해 포스트맨을 켜놓도록 합니다.
필요한 API를 정리했다면, 라우터에 어떠한 API가 필요한지 미리 주소부터 결정해놓고 로직을 작성합니다.
POST 네트워크 방식의 '/review/create' 라우터를 생성합니다.
외부에서 즉, HTML 화면에서 사용자로부터 리뷰를 작성 받아 서버로 전송할 계획입니다. 전송할 때는 요청 API의 body에 담겨 옵니다. 다시한번 상기시켜보자면, POST 네트워크 방식의 API 요청 방식은 body라는 주머니가 항상 달려있고, 이 주머니에 데이터를 넣어서 서버로 전달해줄 수 있습니다.
따라서 '/review/create' 에서는 req.body에 데이터가 담겨 있게 됩니다. 우린 review라는 키값으로 리뷰데이터를 보낼 예정입니다.
또한 영화 정보도 필요합니다. 어떤 영화의 어떤 리뷰인지가 중요정보이니, 영화 idx 정보를 보냅니다.
이렇게 req.body.review, req.body.moive_id 두 정보를 받아서 데이터베이스에 저장합니다.
데이터베이스에는 현재 users라는 테이블만 존재하기 때문에, review라는 테이블을 만듭니다.
model 폴더에 필요한 테이블을 만들고 db.js에 "나 이런 테이블 만들었따!" 라고 외치듯 새로이 생성한 테이블을 임포트 시켜줍니다.
db.reviews.create(데이터) 형식으로 화면으로부터 받은 데이터를 저장합니다.
혹시 req.body.review안의 정보가 비어있거나, 이상한 내용이 담겨 있을 수도 있습니다. 그럴땐 저장하기전에 한번 검사를 해줄 수 있습니다.
if 조건문으로 req.body.review == '' 과 같이 비어있는지 검사를 한 후 , 비어있으면 res.send()로 내보냅니다. API요청에 대한 모든 응답은 req.send로 해야합니다. 그림파일을 보내는게 아니라 데이터를 보내는거니까요! 그럼 ajax에서 데이터를 받아서 확인한 후, success값이 200인지 400인지에 따라 다른 팝업을 띄울 수 있습니다.

4. 리뷰 읽기 API 만들기
특정 영화를 클릭하면, 영화 아이디를 서버로 보내고, 해당 영화 아이디 앞으로 작성된 리뷰들을 데이터베이스에서 가져옵니다. → 가져온 데이터를 API를 요청한 프론트, 즉 HTML 화면에서 받아 사용하는게 큰 시나리오입니다.
영화 아이디를 보내고 리뷰 데이터를 요청하는 API는 GET 방식으로 생성하려 합니다. GET 방식에서 데이터를 서버로 보내는 방법을 상기시켜보면, 이름표에 꼬리표를 붙이듯이, 주소 뒤에 ?를 두고 키=값의 쌍으로 데이터를 서버로 보낼 수 있었습니다.
프론트, 즉 HTML에서 리뷰를 조회했던 API는 라우터에서 "/review/read"로 만들 계획입니다.
받을땐 req.query 객체 안에서 넘겨받은 키값을 꺼내 사용하면 됩니다. 넘길땐 movie_id로 넘기고자 합니다.
받은 영화 아이디를 가지고 db.reviews.findAll(조건) 형태로 데이터베이스에서 조회를 할 수 있습니다.
만약 정상적인 요청이 아닌, 비 정상적인 요청 예컨대 영화 아이디가 누락되었거나 문자가 넘어올 수 도 있으므로 이부분에서도 서버적 처리를 해주는게 좋습니다. 모두다 안전을 위함이죠!
if 조건문, req.query.movie == undefined를 통해 데이터가 비어있는 상황을 가정하여 분기문을 작성해줍니다.
역시나 API 요청에 대한 응답은 모두 res.send로 응답해줘야 하므로, 프론트단의 Ajax에서 서버로부터 받은 데이터안의 success의 값이 200인지 400인지에 따른 다른 팝업을 사용자에게 보여줄 수 있습니다.

5. 백엔드 총 정리!
﻿최종적으로 직접 만든 API를 화면과 연결합니다. == 즉, 프론트와 백엔드를 연결합니다. == 즉, 여러분은 풀스택 개발자가 된겁니다.
fullStack 개발자라고 해서 거창한게 아닌, 화면과 기능을 직접 모두 구현할 수 있다면 풀스택 개발자입니다. 이렇게 한 웹 사이트를 직접 프론트와 백엔드까지 구현할 수 있게 되었습니다.
전체적인 웹 서비스의 그림을 이랬습니다. 직접 모두다 만들고 나면 웹 개발자, 웹 풀스택, 프론트, 백엔드 개발자란 타이틀이 어렵지 않게 다가옵니다.
그럼 마지막으로 함께 만든 API을 프론트에 붙여보도록 합시다.
기존 개발자 사관학교에서 제공했던 API를 이용할 땐, 주소의 full url을 작성했습니다. 해당 API는 외부에서 제공해주는 API이므로 집주소의 모든 정보를 적어야 요청이 가능했죠.
하지만 지금은 집안에 웹 서버가 존재하게 되었습니다. 마치 옆방에 있는 동생을 불러 불좀 꺼달라는 식의 명령이라 생각해야합니다. 따라서 full url이 아닌 localhost 부분 즉, 방 주소만 적으면 됩니다.
리뷰 작성 ajax url 부분에 '/review/create'라 넣습니다. 즉 http://localhost:3000 부분이 없어도, 지금 우린 같은 집 == 서버에서 그림파일도 보여주고 데이터도 주고 받고 하고 있기 때문에 모두다 알고 있게 됩니다. 
/review/create란 주소가 어디에 있는 주소를 뜻하는지 말이죠!
그렇다면, 3교시때 더 자세히 다루겠지만, 여러분들이 만든 API를 다른 동료가 쓰려면 어떻게 해야할까요? 다른 사람들도 여러분 집주소를 알 수 있게끔 임대 주택, 즉 임대 서버에 여러분 웹서버를 올리고 공인 IP를 받은 뒤 다음과 같이 API를 제공해줘야 합니다. http://52.132.123.23/review/create
